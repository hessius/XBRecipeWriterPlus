# M5 Phase 4: Shelves — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second way into a library that has grown past scanning: a grid of shelves you pass through to pick a lens, and a way to make a shelf of your own by choosing what goes on it.

**Architecture:** Every shelf is a query, and the queries already exist. An auto shelf is a `FilterId` from `library/libraryFilters.ts` with a count from `countRecipesByFilter`; a manual shelf is a tag from `recipe_tags`. There is no `shelves` table and no `shelf_members` table, so nothing can go stale and nothing has to be migrated. The grid is a second drawing of the filter vocabulary phase 3 derived, and tapping a shelf applies that filter and returns to the list. Creating a shelf is applying a tag, so shelf creation is the tag editor wearing a friendlier word.

**Tech Stack:** TypeScript, `expo-sqlite` (sync API), Tamagui, Jest with `@testing-library/react-native` v14, and the `node:sqlite` harness in `library/__tests__/`.

**Design docs:**

## Scope

**In scope:** the shelf query model as a read-through over what exists, the grid,
the stock auto shelves with their suppression rules, the `YOUR SHELVES` /
`AUTO SHELVES` vocabulary, shelf creation through the selection picker, the
view segmented pair deferred from phase 3, and the `shelves` help topic.

**Out of scope, and already argued elsewhere:**

- **Shelf ordering.** #111, deferred with its three options recorded.
- **Per-author shelves.** #126. The rail speaks the label; nothing supplies the
  distinct-author query. It belongs here by subject and is filed because it is
  a build rather than a wiring, and the grid ships without it.
- **`ShelfMark` variants.** The design says the mark is unsettled and going to
  testers. Ship one mark behind the existing pattern, not three behind a switch.
- **Nested shelves, user-authored queries, shelf sharing.**

## Before you start

Read, in this order:

1. §Shelves of the design, all six subsections. The data model is the whole
   feature and it is one page.
2. `library/libraryFilters.ts`. The grid's auto half is this file drawn as
   tiles. If a task here wants to restate the vocabulary, the task is wrong.
3. `hooks/useLibraryQuery.ts` and `components/LibraryRail.tsx`, which the picker
   reuses rather than reimplements.

**The rule that keeps this phase small:** nothing about a shelf is stored.
A task that adds a table has misread the design. A shelf is a query, its
membership is a tag or an index predicate, and both already round-trip through
`buildBackup` because they live in the blob.

### Task 1: The `libraryView` setting

- [ ] Add `libraryView` to `Settings.DEFAULTS` with the value `"list"`.
- [ ] Add it to `settingsSnapshot()` in `app/settings.tsx`. `DEFAULTS` alone
      does not put a key in a backup, which is how `showHints` once went
      missing.
- [ ] Test: it round-trips through a backup, and an unknown stored value falls
      back to `"list"` rather than rendering neither half of the pair.

### Task 2: The shelf vocabulary

- [ ] `library/shelves.ts`: a `Shelf` type (`id`, `label`, `kind`, `count`) and
      a builder that assembles the list from two sources already in the app:
      `STOCK_FILTER_ORDER` with `countRecipesByFilter`, and the distinct tags
      with their counts.
- [ ] Apply the design's suppression to **derived shelves only**: an auto shelf
      is not drawn below 3 members nor above 80% of the library. A manual shelf
      is always drawn, because a person made it on purpose.
- [ ] Test the boundaries exactly: 2 and 3 members, and 80% and 81% of the
      library. Suppression rules stated as percentages are where off-by-one
      lives.

### Task 3: Counting tags

- [ ] `RecipeDatabase.countRecipesByTag()`: one `GROUP BY tagKey` over
      `recipe_tags`, returning the display `tag` alongside its count.
- [ ] Return the display spelling, not the key. `tagKey` is for matching and
      would show the user a lower-cased version of their own word.
- [ ] Test: two spellings of one tag count as one shelf, and the label is the
      spelling the user typed.

### Task 4: The shelf tile

- [ ] `components/ShelfTile.tsx`: label, count, and the shelf mark. One mark
      implementation, the accent field with a dot matrix glyph for auto shelves
      and the derived mark for manual ones.
- [ ] Accessibility label names the kind and the count, because the mark carries
      that distinction visually and a reader gets nothing from it.
- [ ] No fixed pixel colours. `constants/colors.ts` only, and `palette.none` for
      an unfilled state.

### Task 5: The grid

- [ ] `components/ShelfGrid.tsx`: two sections, `YOUR SHELVES` then
      `AUTO SHELVES`, Doto caps matching `NO RECIPES YET`.
- [ ] A section with nothing in it is not drawn, heading included. A heading
      over an empty section is a promise the app cannot keep.
- [ ] Empty state: a library with no tags and no qualifying auto shelf shows one
      line explaining what a shelf is, not an empty grid.

### Task 6: The view segmented pair

- [ ] Insert `SegmentedControl` into the rail's leading cluster, between search
      and sort, which is where phase 3's comment says it goes.
- [ ] Bind it to `libraryView`. Switching writes the setting, so the choice
      survives a relaunch, per §"Last view is remembered".
- [ ] Check the rail still fits at 320 pt with the pair present. Phase 3 left
      `COLLAPSE_SHRINK = 140` unrevisited when the rail arrived, and this adds
      to the same row.

### Task 7: Tapping a shelf

- [ ] Applies the shelf's filter and returns to list view. The grid is
      somewhere you pass through, not a second home.
- [ ] While a shelf is applied, the filter chips dim: in that view the shelves
      are the filters, and offering both offers the same narrowing twice.
- [ ] Test the round trip: grid, tap, list narrowed, back to grid, and the
      applied shelf still reads as applied.

### Task 8: Selection mode

- [ ] The picker is the library screen with a tick per row and a bottom bar,
      not a new screen. Same rail, same chips, same search.
- [ ] **Filters compose with selection.** Narrow to tea, tick three, clear the
      filter, and the three stay ticked. This is the test that matters most:
      selection lives above the query, not inside the list.
- [ ] A `SELECTED (n)` chip, so changing the lens cannot hide the user's own
      choices.
- [ ] The bottom bar counts the shelf, not the view: `4 ON THIS SHELF`, never
      the number visible under the current filter.

### Task 9: Creating and emptying a shelf

- [ ] Creation ends in the picker rather than starting with an empty box, which
      follows from a manual shelf having nowhere to exist without members.
- [ ] Removing the last member removes the shelf, behind a confirmation that
      says so before it happens rather than after.
- [ ] Test: a shelf that loses its last member is gone from the grid, and the
      recipes are not.

### Task 10: The help topic

- [ ] A `shelves` topic in `constants/recipeHelp.ts`, which is the existing
      data-driven mechanism behind `showHints`. No tutorial and no new voice.

### Task 11: The sweep

- [ ] `npm run typecheck`, `npm run lint`, `npm test`, `npx expo-doctor`.
- [ ] Re-read every comment written during the phase against the code it sits
      on. Every review pass on phase 3 found at least one comment describing
      something that had since changed.
- [ ] Update §Shipping order of the design to mark phase 4 shipped, and the
      roadmap's M5 row with it.

## What "done" looks like

- The library has two front doors and remembers which one you use.
- The grid shows shelves that are queries, so none of them can disagree with
  the list they open.
- A shelf can be made by choosing recipes, and choosing survives filtering.
- No new table, no migration, and no second copy of the filter vocabulary.

## Verification owed beyond CI

- 320 pt: the rail with the pair, and the picker's bottom bar over the list.
- A library with no tags, to see the grid's empty half rather than infer it.
- A library of one tag with one member, which is the suppression boundary a
  manual shelf is deliberately exempt from.
